## 1. Datasets

We evaluate the resolution pipeline on a synthetic dataset of **2,946** free-text interest strings. These strings were generated by:
1.  Taking the canonical concept names from our CS Ontology subset.
2.  Applying perturbations: common typos, synonym substitution (e.g., "ML" -> "machine learning"), and adding noise words ("stuff", "things").
3.  **Planted Cases:** We intentionally injected a set of "junk" strings that do not map to any valid concept in the ontology (e.g., "vacation photos", "random thoughts") to test the model's ability to reject invalid mappings rather than hallucinating a match.

We also maintain a smaller, hand-curated set of ~50 real strings collected from early internal testing for sanity checks, but these are not part of the main automated benchmark.

## 2. Metrics

*   **Resolution Rate:** % of strings that map to a canonical concept without human intervention.
*   **Adjudication Agreement:** For cases reaching the LLM stage, we measure agreement between `qwen3.8` (our production model) and a gold-standard label (assigned by John + Noor).
*   **Junk Rejection Rate:** % of planted junk strings correctly rejected by the LLM adjudicator.
*   **Latency (p95):** Time from request to resolved concept, measured in the local Ollama environment.

## 3. Baselines

We compare against:
1.  **Exact Match Only:** Simple string equality against the ontology aliases.
2.  **Embedding Only:** Nearest neighbor search on `nomic-embed-text` vectors with a fixed threshold (no LLM adjudication).
3.  **Cloud API (Reference):** We ran a subset of 100 strings through a standard cloud LLM API for comparison, but due to privacy constraints (D3), this is not our primary system. *Note: We only have qualitative comparisons here; need to formalize if space allows.*

## 4. Results (as of 14 Sep)

| Metric | Full Pipeline (qwen3.8) | Embedding Only | Exact Match |
| :--- | :--- | :--- | :--- |
| **Resolution Rate** | 99.1% | ~85% (est.) | ~60% (est.) |
| **LLM Usage** | 3.6% of traffic | N/A | N/A |
| **Adjudication Agreement** | 39/40 (97.5%) | N/A | N/A |
| **Junk Rejection** | 10/10 (100%) | Low (hallucinations) | High (rejects all) |
| **p95 Latency** | 0.9s | ~0.2s | <0.01s |

**Key Observations:**
*   The four-stage pipeline successfully offloads 96.4% of requests to cheap deterministic methods (alias/trigram/embedding), keeping LLM calls rare.
*   `qwen3.8` outperforms the smaller `qwen3-4b` model on junk rejection (10/10 vs 8/10) and agreement (39/40 vs 37/40). The small model is 3.6x faster but less reliable for edge cases.
*   The embedding auto-accept threshold (>=0.92) rarely fires in practice; most successful embeddings fall into the 0.85–0.92 range and require adjudication or trigram support.

## 5. Threats to Validity

1.  **Synthetic Data Bias:** Our 2,946 strings are generated from known concepts. Real user input is messier (multilingual, slang, out-of-domain). We need real pilot data to validate generalizability.
2.  **Ontology Coverage:** The CS Ontology subset is limited. If a user's interest falls outside this domain, the system will likely fail or reject it. This is a scope limitation, not a bug, but should be noted.
3.  **Local Hardware Variance:** Latency results are specific to the ASUS GX10 (128GB RAM) with Ollama. Cloud deployments may have different trade-offs (higher latency for cold starts, lower for warm).
