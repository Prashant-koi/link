# Latency Blocker — Resolution Pipeline

**Date:** Wed 26 Aug 2026
**Author:** Chen Diaz
**Status:** Fix implemented, measuring improvements. Target: p95 < 1.0s by Mon 31 Aug.

## The Problem

Noor and John flagged that the resolution pipeline is too slow for a demo. When a user submits interests, we are waiting **~4.2s (p95)** before they see any suggestions or "why you connect" cards. For a hackathon demo, that feels like the app is broken.

**Root Cause Analysis:**
1. **Model Unloading:** Ollama unloads models from RAM after idle periods to save memory. When a request comes in, it has to reload the model weights.
   - `nomic-embed-text`: ~14s reload time.
   - `qwen2.5-14b`: ~46s reload time (this is the killer).
2. **Unbatched Embeddings:** We were sending interest strings one-by-one to the embedder. Each call has fixed overhead (model load check, HTTP round-trip).

## The Fix Plan

Implemented today (Wed 26 Aug):

1. **Keep-Warm Heartbeat:**
   - Added a background job in the worker that pings Ollama every **2 minutes**.
   - It generates a dummy embedding and a dummy completion (tiny prompt) to keep both models loaded in VRAM/RAM.
   - *Note:* This uses some idle compute, but on the GX10 box with 128GB unified memory, it’s negligible compared to the 46s reload penalty.

2. **Batching Embeddings:**
   - Changed the embedder client to batch up to **256 strings** per request.
   - This reduces the number of HTTP calls and lets Ollama process them in one pass if the model is warm.

3. **Concurrency Limit:**
   - Set `instruct_concurrency = 2` for the LLM adjudication step.
   - Prevents us from overwhelming the GPU/CPU with parallel thinking tokens (even with reasoning off, qwen2.5-14b is heavy).

## Measurements

**Before Fix (Wed 26 Aug, ~10:00 AM):**
- p50: 3.1s
- p95: 4.2s
- Max: 48s (caught the model unload)

**After Fix (Wed 26 Aug, ~2:00 PM):**
- p50: 0.7s
- p95: 1.8s
- Max: 2.2s
*Still slightly above target, likely due to variance in the first few requests after a restart.*

**Projected (by Mon 31 Aug):**
- We will monitor over the weekend. If the heartbeat holds, p95 should stabilize around **0.9s**.
