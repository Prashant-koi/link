# Scope Cut Meeting — Tue 18 Aug 2026

**Present:** John, Jane, Chen, Noor, Mei
**Scribe:** John
**Status:** Decided (D5)

## TL;DR
We are cutting the native mobile app and the calendar integration. We ship a responsive web app only. This was not an easy call, but it is necessary to protect the core "why you connect" experience and the local-model pipeline before the 12 Sep deadline.

## Context
It has been three weeks since we started building in earnest. The resolution pipeline (exact -> trigram -> embedding -> LLM adjudication) is working locally on the GX10 box, but we are still seeing latency spikes when Ollama unloads idle models. We also have zero messaging UI built, and the "atlas" visualization is still a sketch on Mei's whiteboard.

We have 25 days until the hackathon weekend (Sat 12 Sep). The team consensus was that trying to maintain three separate codebases (iOS, Android, Web) plus a calendar sync service would burn out Jane and Chen before we even get to the demo polish. We need to focus our energy on the core value prop: surfacing connections with clear explanations.

## What is being cut
1.  **Native Mobile Apps:** No React Native or Flutter work. We will not ship an App Store/Play Store build.
2.  **Calendar Integration:** No Outlook/Google Calendar sync. The "find a time to meet" feature will be simplified to a static link or a manual text field for now, if we have time. It is not a priority.

## What stays (Non-negotiables)
1.  **Responsive Web App:** Must work well on mobile browsers. This is our primary interface.
2.  **Resolution Pipeline:** The local AI stack (nomic-embed-text + qwen3.8) must be stable. We cannot afford to debug model loading issues during the demo.
3.  **"Why You Connect" Explanations:** This is our differentiator. If we drop anything, this stays. The LLM adjudication step needs to be robust.
4.  **Double Opt-In Messaging:** Per D4 (Mei/Diego), nobody can message someone who hasn't accepted. This is a privacy requirement, not a feature.

## Jane's Concerns & Mitigations
*   **Concern:** "I feel like we're throwing away a lot of the 'campus app' vibe if it's just a website."
*   **Mitigation:** We are investing in PWA capabilities (manifest.json, offline support for cached data) so it *feels* like an app on mobile browsers. Mei is designing the UI to be thumb-friendly and fast. We will not have the polish of a native app, but we will have the core functionality.
*   **Concern:** "Calendar integration was my favorite feature."
*   **Mitigation:** It's a nice-to-have, not a must-have. The core value is *finding* people to talk to, not scheduling. We can always add calendar sync in a v2 post-hackathon if we win (or even if we don't).

## New Priorities (Ranked)
1.  **Stability of Local AI Pipeline:** Fix the Ollama unloading issue. Batch embeddings. Ensure p95 latency is under 2 seconds. (Owner: John/Noor)
2.  **Core UI Flow:** Onboarding -> Interest Input -> Atlas View -> Person Detail -> "Why Connect" -> Message Request. (Owner: Jane/Mei)
3.  **Backend Hardening:** Rate limiting, basic auth, and ensuring the Postgres job queue doesn't fall over under load. (Owner: Chen)
4.  **Demo Script:** Prepare a clear narrative for the judges. Focus on privacy (local models) and explainability (why you connect). (Owner: All)
