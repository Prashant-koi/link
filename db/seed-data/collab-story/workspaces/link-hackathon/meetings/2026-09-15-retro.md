## Context
Hackathon weekend was Sat 12 – Sun 13. We placed **3rd in the Dropbox track**. It’s a solid result for a weekend build, but we had some rough edges that are now blocking the next steps (paper + pilot). This doc is my attempt to capture what went right, what broke, and what we owe each other before deadlines hit.

---

## Went Well

- **The "Why" Explanations:** This was the standout. The judges specifically praised the adjudication step where the LLM explains *why* two people connect. It felt less like a matching algorithm and more like a recommendation engine with a brain.
    - *Credit:* Noor’s pipeline design (exact -> trigram -> embedding -> LLM) meant we only paid the latency cost for hard cases.
- **Local AI Stack:** Running `qwen3.8` and `nomic-embed-text` locally on the GX10 box was a huge win for the privacy narrative. When judges asked about data handling, we could say "it never leaves the machine." That resonated well with the Dropbox team.
- **The Demo Flow:** Pivoting to start on a single person’s connection explanation (D9) worked perfectly. Starting with the Atlas graph was too abstract; the specific example hooked them immediately.

## Didn’t Go Well

- **Latency Spikes:** Even with the keep-warm heartbeat, we saw p95 latency creep up during the demo when multiple judges clicked around simultaneously. The 2-minute heartbeat might be too aggressive for a 128GB box under load, or our concurrency limit (2) is a bottleneck.
- **Auth is Still Fragile:** We shipped with basic session tokens. Chen flagged this as a "hackathon hack" and it needs to be hardened before any real users touch it.
- **No Mobile/Calendar:** We cut these (D5), but the lack of calendar integration meant we couldn’t show the "meet up" flow fully. It’s a gap for the pilot.

## Judges’ Feedback

1.  **Privacy:** Hard questions about how we handle PII in the free-text interests. They wanted to know if we log raw strings.
    *   *Our Answer:* We cache resolved aliases, but raw strings are transient. We need to document this clearly for the pilot.
2.  **Scoring Transparency:** They liked the IDF weighting but asked why some "obvious" connections were ranked lower than niche ones.
    *   *Action:* We need a better UI tooltip explaining the rarity weight vs. direct match trade-off.
3.  **Model Consistency:** One judge asked if we’d tested smaller models for cost/latency. We mentioned the 4B test (Noor/John, Mon 14 Sep) where it failed on junk strings. They seemed impressed we had that data point ready.
